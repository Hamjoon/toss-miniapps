## Audit Checks

- No committed live ad IDs in frontend runtime source.
- Toss test IDs are injected by console test wrappers, not generated by runtime source.
- Release wrappers reject `ait-ad-test-*` values in release env/output.
- Full-screen ads are preloaded before show and are optional side effects.
- Full-screen ads are not shown in payment, auth, account-opening, or other critical flows.
- Back/close navigation is not trapped or blocked for ad exposure.
- Rewarded-ad reward grants are not wired to click/dismiss events.
- Banner slots do not disguise ads as service content or primary app CTAs.
- Banner and full-screen ads are not attached while hidden behind another ad surface.
- Ads are separated from high-frequency game controls to reduce accidental taps.

## Follow-Ups

- `App List - Released` has duplicate metadata for `이번주 개봉영화` and `다음 쉬는날`: both currently show `appName: offday-calendar` and mini-app id `48158`. Confirm the released console app name/id for `이번주 개봉영화` before editing the list.
- 7 repos still allow `.env.local` as a release ID source in `build-console.sh`. That can accidentally make local dev serve live ad IDs because Vite also auto-loads `.env.local`. `toss-thisweek-movie` and `toss-offday-calendar` already use the safer `.env.production*` / `.env.release.local` precedent.
- Several repos require `VITE_TOSS_AD_INTERSTITIAL_ID` for release even when the app does not use an interstitial. This may create dead console ad groups with zero traffic.
- Manual device QA is still required for actual Toss SDK behavior because Apps in Toss sandbox does not support ads.
